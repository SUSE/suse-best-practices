= SAP {dme} on SUSE

== Introduction

This guide describes how to prepare your infrastructure for the installation of {dme} on {rke} using {rancher}.
It will guide you through the steps of:

* Installing {rancher}
* Setting up {rke} clusters
* Deploying mandatory components for {dme}

=== Installing {metallb} on Kubernetes cluster

The following chapter should guide you through the installation and configuration of {metallb} on your Kubernetes cluster used for {dme}.

Before proceeding, ensure you have the following networking resources available for configuration:
* A static IP address allocated for the {metallb} _IPAddressPool_. This address must be outside your DHCP pool range but routable within your network cluster.
* A configured DNS record (A or AAAA) matching your desired domain name that points directly to that allocated IP address.

The DNS name will be used later in this guide and will be referred to as *<LB-address>*.

TIP: If you have no control over your DNS and are running an proof of concept like setup, you can just add _.sslip.io_ to your IP address. *This is not considered a best practice and is strongly discouraged for production environments.*

==== Updating Helm values for the Proxy Cache

To route image requests through your newly created {reg} Proxy Cache (configured in <<prepareRegistryProject>>), you must update the SAP {dme} Helm `values.yaml` file.

Locate the `global.dockerRegistry` parameter in your custom `values.yaml` file and update it to point to your {reg} FQDN and the specific proxy cache project name.

Modify your `values.yaml` file as follows:

[source, yaml]
----
global:
  dockerRegistry: "<PRIVATE_REGISTRY_FQDN>/<PROXY_PROJECT_NAME>"
  # Example: "suse-registry.example.com/proxy-cache-project"
  security:
    imageCredentials:
      username: "<SPR_USERNAME>"
      password: "<SPR_PASSWORD>"
----

NOTE: Ensure that the username and password provided in the `imageCredentials` block correspond to a registry account that has at least read permissions (`Pull` role) assigned within the specified proxy project.

{dme} requires a Kubernetes Ingress Controller to be installed in the cluster, which handles the traffic routing to {dme} components.
As of today, there are two supported Gateways:
* Istio
* Nginx

In this chapter we'll describe how to deploy both of them and how to prepare them for {dme}

==== Istio

include::SAP-DME-Istio.adoc[leveloffset=2, tags=**]

==== Nginx

[WARNING]
====
Ingress NGINX went End-of-Life in March 2026 as stated in https://kubernetes.io/blog/2025/11/11/ingress-nginx-retirement/
We therefore highly recommend to use {istio} for the usage with {dme}.
====

Nginx is deployed on {rke} by default for {rke} cluster version prior to 1.36. If not explicitly opted out in the cluster creation phase in {rancher} UI or by adding installation suffixes when using the installation script, Nginx will be deployed on those clusters.

For {rke} clusters later than 1.36, Nginx can still be selected in the {rancher} UI during cluster creation.

==  Deploying {dme}

At this point you should have installed all mandatory components and you are ready to deploy {dme}.
The next step is to create an edge device as described in https://help.sap.com/docs/sap-digital-manufacturing/setup-and-operations-guide-for-sap-digital-manufacturing-for-edge-computing/create-edge-device?locale=en-US

Afterwards, you can follow the instructions at https://help.sap.com/docs/sap-digital-manufacturing/setup-and-operations-guide-for-sap-digital-manufacturing-for-edge-computing/install-with-helm?locale=en-US where you can skip the certificate creation, as you already created them in the previous chapters.

If you followed this whole guide, you can find an example of what the _values.yaml_ may look like.

[IMPORTANT]
====
The excerpt below shows an example using {istio}, {dex}, {pg} and Kafka with values that were described in this guide.
For a better overview, it shows the values without using the _External Secrets_ option.
====

[source, yaml]
----
deviceId: '<your-device-id>'
connectionString: <your-connection-string>
global:
    tenantId: '<your-tenant>'
    dockerRegistry: '<RSBC-Repository-URL>'
    gateway:
        hostname: <LB-address>
    storageClass: longhorn
    uaaUrl: '<your-uaaURL>'
    uaaClientId: <your-uaaClient>
    uaaClientSecret: <your-uaaClient-Password>
    ingressType: istio
    istioNamespace: istio-system
    ingressCACertificate: tls-secret-cacert
    ingressServerCertificate: tls-secret
    dex:
        useEmbedded: false
    dexIssuer: https://<dex-server-URL>
    dexCACertificate: dex-ca-secret
    dexClient:
        clientID: sap-dm-edge-client
        clientSecret: super-secret-password-shared-with-sap-dm
    idpLogoutUrl: https://<your-Rancher-URL>/oidc/logout
    database:
        useEmbedded: true
        type: postgresql
        auth:
            host: "postgres-rw.edgedb.svc.cluster.local"
            port: 5432
            database: "edgedb"
            username: "appuser"
            password: "<your_password>"
    kafka:
        useEmbedded: false
        auth:
          brokers: 'kafka-cluster-kafka-bootstrap.kafka.svc.cluster.local:9092'
          username: 'kafka-user'
          password: '<YOUR_DECODED_KAFKA_PASSWORD>'
    security:
        imageCredentials:
            username: <RBSC-docker-registry-username>
            password: <RBSC-docker-registry-password>
        externalSecrets:
            enabled: false
    size: production
edge-object-store:
    storageClass: longhorn
    hasRWXSupport: true
----

To get a better understanding of the values, you can refer to https://help.sap.com/docs/sap-digital-manufacturing/setup-and-operations-guide-for-sap-digital-manufacturing-for-edge-computing/helm-values

Once the _helm install ..._ succeeded, {dme} is deployed and ready to be used.
For all further steps follow the official documentation by SAP starting with https://help.sap.com/docs/sap-digital-manufacturing/setup-and-operations-guide-for-sap-digital-manufacturing-for-edge-computing/enable-and-trigger-initial-load?locale=en-US
