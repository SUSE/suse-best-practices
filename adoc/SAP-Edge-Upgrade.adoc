
# tag::intro[]
== Upgrade guidance

To upgrade SAP edge application clusters, we recommend upgrading Rancher first, then Kubernetes, 
and finally the operating system. For more information about preparation guidelines, see 
https://www.suse.com/support/kb/doc/?id=000020061.
# end::intro[]

# tag::eic[]
=== Upgrading {eic}

Before upgrading your {eic} instance, ensure the target version was release for your {rke} cluster version:
https://me.sap.com/notes/3247839

Find detailed instructions on how to upgrade {eic} at
https://help.sap.com/docs/integration-suite/sap-integration-suite/upgrade-edge-integration-cell-solution


To upgrade the {eic} instance, navigate to the Edge Nodes in the {break elm} user interface.
Select the edge node to upgrade. The *Deployments* view displays the deployed solutions and their versions.

Click the options menu (three dots *...*) and select *Upgrade*, as show in the following image:

image::SAP-EIC-Upgrade-EIC.png[title=EIC Upgrade example,scaledwidth=99%,opts=inline,Embedded]

The following steps describe the upgrade process, including how to select the target version. 
If dependencies exist between deployments, {elm} displays them and includes them in the upgrade.

image::SAP-EIC-Upgrade-Dependencies.png[title=EIC Upgrade example,scaledwidth=99%,opts=inline,Embedded]

If you skipped multiple {eic} versions, perform intermediate upgrades before installing the target version. 
Repeat the upgrade steps for {eic} until you reach the target version.

=== Upgrading {rke}

This chapter describes how to upgrade {rke}.

IMPORTANT: We recommend upgrading sequentially through each minor version. 
Before upgrading to the next minor version, upgrade to the latest patch level of the current version.

==== Upgrading {rke} using {rancher}

IMPORTANT: This is the preferred way to upgrade all {rke} clusters managed by {rancher}. 

If you deployed the {rke} cluster using {rancher}, you can upgrade it through the same interface. 
To begin, navigate to the *Cluster Management* view.

image::SAP-Edge-Cluster-Management.png[title=Cluster Management Overview,scaledwidth=99%,opts=inline,Embedded]

++++
<?pdfpagebreak?>
++++

Click the menu icon ("hamburger menu") for the cluster you want to upgrade, and select *Edit Config*.

image::SAP-Edge-Cluster-Management-Edit.png[title=Cluster Management Edit Config,scaledwidth=99%,opts=inline,Embedded]

++++
<?pdfpagebreak?>
++++

Scroll down to the *Cluster Configuration* section, where you find the field *Kubernetes Version*.

image::SAP-Edge-Cluster-Management-Edit-K8s.png[title=Upgrade Kubernetes,scaledwidth=99%,opts=inline,Embedded]

Select the Kubernetes version you want to upgrade to and click *Save* at the bottom right corner of your window.

++++
<?pdfpagebreak?>
++++

==== Upgrading {rke} without {rancher}

When upgrading {rke} without {rancher}, consider the following two strategies:

1. In-place upgrade: Upgrades existing nodes sequentially.
2. Rolling upgrade: Adds a temporary node running the new version.

WARNING: 
Upgrading nodes out of sequence or simultaneously can cause cluster instability.
Regardless of the strategy chosen, we recommend to upgrade control plane nodes 
before worker nodes. Always upgrade nodes sequentially.


===== Upgrading with temporary nodes

To upgrade a cluster using temporary nodes, add a new node running the new version.

Initially, the landscape appears as shown in the following image: 

image::SAP-Edge-Upgrade-init.svg[title=Upgrade RKE2 init,scaledwidth=99%,opts=inline,Embedded]

After adding the new node, the landscape shows:

image::SAP-Edge-Upgrade-add-CP.svg[title=Upgrade RKE2 add,scaledwidth=99%,opts=inline,Embedded]

After adding the new node and deploying all mandatory components, remove non-upgraded nodes from the cluster:

image::SAP-Edge-Upgrade-rm-CP.svg[title=Upgrade RKE2 rm,scaledwidth=99%,opts=inline,Embedded]

Before removing a node from the cluster, cordon and drain the node. 
Cordoning prevents scheduling new workloads on the node, and draining evicts running workloads so they can be rescheduled elsewhere.

Follow the same procedure to upgrade worker nodes:

image::SAP-Edge-Upgrade-worker.svg[title=Upgrade RKE2 worker,scaledwidth=99%,opts=inline,Embedded]

===== Upgrading without temporary nodes

Before upgrading an existing node, cordon and drain the node.
To do so, run the following commands:

[source, bash]
----
kubectl cordon <node-name>
kubectl drain <node-name> --grace-period=600
----

The upgrade method depends on how you originally installed {rke}. 
For details on manual upgrades, refer to https://docs.rke2.io/upgrades/manual_upgrade.

IMPORTANT: You must upgrade using the same method used for installation. 
For example, if you installed {rke} via RPM, do upgrade using the installation script.

This guide describes how to upgrade using the installation script.

To proceed, connect to ther {rke} node and run the following command. 
Replace the version placeholder with your the target version:

[source, bash]
----
curl -sfL https://get.rke2.io | INSTALL_RKE2_VERSION=vX.Y.Z+rke2rN sh -
----

Find a list of {rke} versions at https://github.com/rancher/rke2/releases .

After running the script, wait one minute before restarting the {rke} service.
To restart the service on a control plane node, run the following command:

[source, bash]
----
sudo systemctl restart rke2-server
----

To restart the service on a worker node, run the following command:

[source, bash]
----
sudo systemctl restart rke2-agent
----

When the service has restarted, uncordon the node to resume scheduling:

[source, bash]
----
kubectl uncordon <node-name>
----

Repeat these steps for every machine of the cluster.

=== Upgrading {rancher}

IMPORTANT: We strongly recommend backing up the {rancher} instance before upgrading. 
For instructions, refer to the  
https://ranchermanager.docs.rancher.com/how-to-guides/new-user-guides/backup-restore-and-disaster-recovery/back-up-rancher[Rancher Backup and Restore Guide].

For a detailed overview of the upgrade process, see the upgrade documentation at
https://ranchermanager.docs.rancher.com/getting-started/installation-and-upgrade/install-upgrade-on-a-kubernetes-cluster/upgrades 

This chapter describes the most common upgrade path.

To begin, update the helm repository:

[source, bash]
----
helm repo update
----

Next, back up the configuration parameters of the current Helm deployment:

[source, bash]
----
helm get values rancher -n cattle-system -o yaml > values.yaml
----

To upgrade {rancher}, run the following command and specify the target version:

[source, bash]
----
helm upgrade rancher rancher-prime/rancher \
  --namespace cattle-system \
  -f values.yaml \
  --version=<desired-version>
----

# end::rancher[]

=== Upgrading {harvester}

WARNING: Ensure your {harvester} version is supported and compatible with your {rancher} instance. 
Verify this in the *Harvester & Rancher Support Matrix* at https://www.suse.com/suse-harvester/support-matrix/all-supported-versions/harvester-v1-5-x/.

Before upgrading {harvester}, run the pre-check script available at 
https://github.com/harvester/upgrade-helpers/tree/main/pre-check/v1.x.
This script ensures that the cluster is in a healthy state and ready to be upgraded. 
If any issues are found, resolve them before proceeding.
It is not necessary to run the script on all nodes, you only need to run it on a single node.

In addition to running the pre-check script, review the official upgrade documentation at 
https://docs.harvesterhci.io/v1.5/upgrade/index, specifically the sections covering the 
upgrade path from your current version to the target version.

You can trigger the upgrade directly from the {harvester} user interface. 
When an upgrade is available, an *Upgrade* button will appear 
in the upper right corner of the Dashboard, as displayed in the following image:

image::SAP-Edge-Upgrade-Harvester-Upgrade-Button.png[title=Harvester upgrade available,scaledwidth=99%,opts=inline,Embedded]

Clicking the *Upgrade* button opens a window  displaying all the target versions.

image::SAP-Edge-Upgrade-Harvester-Version.png[title=Harvester upgrade available,scaledwidth=99%,opts=inline,Embedded]

After selecting the target version, click *Upgrade* again to start the upgrade process.

=== Upgrading the operating system

Upgrade procedures and commands differ depending on the operating system used. 
This guide describes how to upgrade {slm} , as this is the operating system used in the landscape setup examples.

NOTE: To familiarize yourself with {slm} and the concept of transactional updates, see 
https://documentation.suse.com/sle-micro/{slm_version}/html/Micro-transactional-updates/transactional-updates.html .

Before upgrading the {slm} instance, read the 
https://documentation.suse.com/en-us/sle-micro/{slm_version}/html/Micro-upgrade/index.html[SUSE Linux Micro Upgrade Guide] .

Upgrades of {slm} are only supported from the latest patch level. 
Before upgrading {slm}, ensure the system is up to date.
To update {slm} to the latest patch level, run the following command:

[source, bash]
----
sudo transactional-update patch
----

WARNING: Transactional updates take effect only after a system reboot. Reboot the system to complete the update.


Update {slm} in a similar way to the next version:

[source, bash]
----
sudo transactional-update migration
----
